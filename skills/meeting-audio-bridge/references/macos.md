# Mac：腾讯会议 ↔ 钉钉

## 依赖与安装

Python 3.9+ 用于只读检查和生成方案。Mac 上需要 BlackHole 2ch；双向再加 16ch。两款会议客户端需支持分别选择麦克风、扬声器，并识别虚拟设备。具体菜单位置以当前客户端为准；本仓库未证明每个版本兼容。

如缺失且本次已授权安装，可使用已有 Homebrew：

```sh
brew install --cask blackhole-2ch
brew install --cask blackhole-16ch
```

没有 Homebrew 时使用 [BlackHole 官方安装入口](https://existential.audio/blackhole/)，不要为单次桥接顺带部署整套包管理器。驱动安装可能要求管理员操作或重启，按安装器实际提示处理，不主动重启电脑或正在工作的音频服务。

## 创建多输出设备

在「音频 MIDI 设置」的音频设备窗口左下角 `+` 选择**创建多输出设备**。不要选择“创建聚集设备”。

| 名称 | 成员 | 谁将它用作扬声器 |
|---|---|---|
| Bridge A to B | 实体耳机 + BlackHole 2ch | 腾讯会议 |
| Bridge B to A | 实体耳机 + BlackHole 16ch | 钉钉（双向） |

旁听模式只创建第一项，钉钉直接使用耳机。

优先使用有线/USB 耳机。采用各成员都支持的同一采样率（通常先尝试 48 kHz，不支持则选共同值），非主时钟设备开启漂移修正。官方建议用一个双声道设备作主设备；不要把 16ch 作为首选主时钟。多输出的立体声映射应落在 BlackHole 的 1–2 声道，实际用电平和远端测试确认，不能假定 16ch 客户端一定读取正确声道。

若采用蓝牙耳机，其麦克风启用可能改变音频模式/采样率，建议改用 Mac 内置或 USB 麦克风。音量键对多输出设备可能不生效；在设备或应用内调音量。不要为解决问题加上未静音的内置扬声器，导致声学回授。

官方指南针对系统级播放给出默认输出切换步骤；本场景只将 A/B 的应用输出分别设为多输出设备，避免转发系统通知。只有应用不能独立选择输出时才讨论系统默认输出的替代方案，且重新检查反馈路径。

## 客户端选择

先让腾讯会议保持静音。在音频设置中：

| 客户端 | 麦克风（待机/本人发言） | 扬声器 |
|---|---|---|
| 腾讯会议 | 实体麦克风 | Bridge A to B |
| 钉钉 | BlackHole 2ch | Bridge B to A（双向）或耳机（旁听） |

同事发言时，把腾讯会议麦克风改为 BlackHole 16ch。钉钉麦克风必须处于开放状态，才能把 A 的声音送给同事；设置阶段可以静音，测试时再按授权开启。退出时先静音再恢复选项。

## 定位故障

- **设备不显示**：通过 Audio MIDI Setup 核实安装；客户端可能需要退出重开。正式会议中不要直接退出，先报告会中限制。
- **你能听到 A，同事听不到**：核对 A 输出设备成员、BlackHole 2ch 1–2 声道电平、钉钉输入选择及静音、麦克风权限；然后检查网络。不要从“驱动文件存在”推断输入有效。
- **你能听到 B，A 远端听不到**：核对返程成员、16ch 1–2 声道、腾讯输入与静音。若客户端不支持该多声道设备，停在已验证旁听状态；不能把正返程合并到 2ch 以求出声。
- **断音/抽吸**：先检查时钟、漂移修正、网络和声道，再单独测试客户端降噪/自动增益/回声处理。先记原值，每次只改一个选项，不能一概关闭所有处理。
- **回声/啸叫**：立即静音腾讯；核查是否同一总线双向使用、软件监听把音频送回自身、有人开了外放或同一人多设备接音频。排除后重新测试。
