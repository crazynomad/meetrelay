# 同时发言：额外的混音要求

当前 skill 自带的确定性方案生成器只支持旁听和切换发言人。请求本机与同事同时发言时，应说明这一边界；可以在另行选定、实际可用的混音器中实施以下矩阵，但不能宣称本仓库已经实现一键混音。

完整三方桥接要为两个目的地生成不同混音：

| 目标 | 应包含 | 必须排除 |
|---|---|---|
| 腾讯会议麦克风 | 本机麦克风 + 钉钉远端声音 | 腾讯会议输出 |
| 钉钉麦克风 | 本机麦克风 + 腾讯会议远端声音 | 钉钉输出 |
| 本机耳机 | 腾讯会议输出 + 钉钉输出 | 本机麦克风监听（默认） |

聚集设备只能提供多组输入声道，不能把它们自动求和。多输出设备只能复制，不能按来源排除。使用单一“系统音频”来源会把两端混在一起，也不满足矩阵。

选择混音器时，核实当前版本能分别捕获两个应用或独立虚拟输入、创建两个独立输出混音、控制返送和静音。如果沿用 BlackHole，应分别规划原始应用输出与混音后的虚拟麦克风总线，避免混音器读写同一个循环通道。不要在通用会议客户端通常只取 1–2 声道的前提下，声称把信号放到 3–4 声道就能自动被识别。

用户要求开源时保持开源约束，不将付费软件当作已获同意的依赖。没有经过核实的可用混音器时，提供切换模式作为明确标注的降级方案，并保留“同时发言未完成”。
